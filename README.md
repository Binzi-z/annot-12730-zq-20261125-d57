# 吊销落盘后目录还能发布吗

获确认的题面位于 task/PROMPT.txt。使用原生 Windows 和标准库，输入与验证使用本地合成数据。

本项目用纯 Go 标准库（Go 1.27，Windows 本地运行）重建柜台系统的**离线插件发布与恢复协议**，
并回答题眼问题：**撤销一旦先落盘，同一目录摘要之后不能再发布——哪怕再次集齐全部批准。**

## 如何运行

```bash
go vet ./...             # 静态检查
go test ./... -count=1   # 包级单元测试 + 10 个演练场景（TestRunAllDrills）
go run ./cmd/drill       # 等价的独立演练入口（同样的 runAll 代码路径）
```

演练产物固定落在 `artifacts/drill-root/`（已在 .gitignore 中忽略），
含每个场景的完整磁盘证据与汇总报告 `run-report.txt`，可直接手工检查。

## 协议模型与不变量

每个插件版本是一个**内容寻址目录** `releases/<代号>/<SHA-256 摘要>/`，
摘要由规范化文件清单（相对路径 + 文件大小 + 逐文件 SHA-256，按路径排序）决定。

1. **两个真正独立的签发者**：批准按签发者背后的真实主体（PrincipalID）去重计票，
   挂名代理（proxy）与本人合计只算一票；门槛 `Quorum = 2`。
2. **任一批准覆盖同一摘要**：批准结构显式绑定代号与目录摘要，异摘要批准无法凑数；
   每份批准是独立的 Ed25519 签名，验证器用注册表公钥逐张重验。
3. **回执先于指针**：写顺序固定为「物化目录 → 回执（承诺凭证）→ 追加历史 → CAS 指针」。
   指针切换是临时文件 + rename 的原子替换，且采用**乐观并发**——事务开工时捕获指针摘要，
   提交时用该值做 CAS；竞争者已推进指针则本事务失败，绝不陈旧覆盖。
4. **撤销先于一切**：发布前先查撤销；撤销文件按摘要命名、须独立签发者签署，
   落盘即永久生效。
5. **失败后只能保留旧版或已合法承诺的新版本**：恢复器不相信内存状态，只扫磁盘，
   沿「当前指针 → 承诺历史由近及远」找第一个已合法承诺且未撤销的版本；
   找不到则移除指针；无承诺/损坏目录移入 `releases/_quarantine/`，撤销目录原地冻结留证。

## 三种崩溃结果的区分（演练 S2–S5）

| 崩溃现场 | 磁盘状态 | 恢复结果 |
| --- | --- | --- |
| 目录改完、回执未写 | 无有效承诺（孤儿目录） | 保留指针上的旧版；孤儿目录隔离 |
| 回执已落盘、指针未切 | 新版本已是合法承诺 | 保留旧版；可凭磁盘回执补切新版本 |
| 指针先落盘且回执齐全 | 完整合法承诺 | 新版本保留 |
| 撤销先落盘 | 指针仍指被撤销版本 | 沿历史回退旧版；同摘要再发布被拒绝 |

另含 S1 事故复盘：朴素系统「先切指针、后补回执」时，重启前后两次调用都报告成功，
但指针指向两个不同摘要，且磁盘上没有任何有效承诺——演练里的原始事故由此复现。


## 局部变更重读计量（S10）

`CachedScanner` 在正式摘要算法外包一层 (大小, 修改时间) 缓存，逐文件记录是否真的读了字节：
冷扫描全量重读；无变更再扫描零字节；改一个文件只重读该文件；新增只重读新文件；
删除不触发任何留存文件重读；重启清空缓存后全量重读，摘要与热路径完全一致。
